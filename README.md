
ZeroTrace — Маршрут цифрового дня

ZeroTrace — интерактивное образовательное веб-приложение по цифровой и информационной безопасности.

Пользователь проходит виртуальный цифровой день продолжительностью примерно 5–7 минут и сталкивается с ситуациями, которые регулярно возникают в реальной жизни: использование смартфона, поездка на такси, подключение к Wi-Fi, работа или учёба, банковские операции, электронная почта и использование домашних устройств.

В каждой ситуации необходимо принять решение. После выбора приложение показывает последствия, объясняет потенциальные риски и предлагает безопасную модель поведения.

В конце прохождения пользователь получает индекс цифровой безопасности, индивидуальный профиль, сильные стороны, зоны риска и рекомендации.

⸻

🎯 Цель проекта

Помочь пользователям повысить уровень цифровой грамотности и научиться распознавать распространённые угрозы информационной безопасности через короткий интерактивный игровой опыт.

Основной принцип:

Ситуация → Решение → Последствие → Объяснение → Рекомендация

⸻

🎮 Игровой маршрут

Пользователь проходит последовательность ситуаций обычного цифрового дня:

📱 Смартфон → 🚕 Такси → ☕ Кафе → 💻 Работа/учёба → 🌐 Интернет → 🏦 Банк → ✉️ Почта → 📱 Социальные сети → 🏠 Дом → 🏆 Результат

Планируется 8–10 игровых сценариев.

⸻

🛡️ Категории безопасности

Сценарии охватывают основные направления цифровой безопасности:

* Пароли и аутентификация
* Фишинг и социальная инженерия
* Wi-Fi и сетевые угрозы
* Приватность
* Безопасность устройств
* Финансовая безопасность

Архитектура предусматривает возможность добавления новых категорий.

⸻

🎲 Игровая механика

Каждый сценарий содержит:

* описание ситуации;
* несколько вариантов ответа;
* категорию безопасности;
* количество баллов за каждый вариант;
* последствия выбранного действия;
* объяснение риска;
* рекомендацию по безопасному поведению.

После прохождения всех сценариев рассчитывается общий индекс цифровой безопасности и результаты по отдельным категориям.

🏆 Итог прохождения

Регистрация и авторизация для прохождения игры не требуются.

⸻

📊 Обезличенная статистика

Приложение собирает статистику прохождений без необходимости идентифицировать пользователя.

Планируется сохранять:

* дату и время прохождения;
* итоговый индекс безопасности;
* результаты по категориям;
* выбранные ответы;
* наиболее частые ошибки;
* распределение результатов по профилям;
* общее количество прохождений.

Персональные данные пользователей не требуются.

⸻

📈 Административная панель

Для просмотра статистики предусматривается административная страница.

Она позволит анализировать:

* количество прохождений;
* средний индекс безопасности;
* распределение индексов;
* результаты по категориям;
* наиболее проблемные категории;
* наиболее частые ошибки;
* популярные неправильные ответы;
* распределение пользователей по профилям.

🧩 Архитектура

Игровой контент отделяется от пользовательского интерфейса и основной бизнес-логики.

Сценарии должны хранить:

* ID;
* название;
* ситуацию;
* категорию;
* варианты ответа;
* баллы;
* последствия;
* объяснения;

Такой подход позволит без существенного изменения приложения:

* добавлять новые сценарии;
* редактировать существующие;
* менять варианты ответов;
* менять систему начисления баллов;
* добавлять категории;
* редактировать объяснения;
* расширять систему статистики.

📝 Пример игрового сценария

🚕 Поездка на такси

Приложение такси запрашивает доступ к:

* контактам;
* геолокации;
* микрофону;
* фотографиям.

Что вы сделаете?

Варианты ответа:

1. Разрешить всё.
2. Разрешить только геолокацию во время использования.
3. Запретить всё.
4. Разрешить доступ навсегда для удобства.

Рекомендуемый вариант:

Разрешить только геолокацию во время использования.

Объяснение:

Для выполнения основной функции приложению такси необходим доступ к местоположению, однако доступ к контактам и фотографиям для обычной поездки не требуется.

Принцип минимальных разрешений уменьшает количество данных, доступных приложению, и снижает потенциальные последствия их утечки.
